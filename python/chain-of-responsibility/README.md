# Chain of Responsibility 责任链模式（Python）

## 意图

使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。
将这些对象连成一条链，并沿着这条链传递该请求，直到有一个对象处理它为止。

## 适用场景

- 有多个对象可以处理同一请求，具体由哪个对象处理在运行时才能确定（如按金额分级审批）
- 想在不明确指定接收者的情况下，向多个对象中的一个提交请求
- 处理者集合应该可以动态指定（增删审批环节而不影响客户端代码）

## 实现方式

`Approver` 是抽象处理者，持有下一环的引用；`handle()` 判断金额是否在自己的权限
`limit` 内，能处理就处理，不能处理就转交 `_next`：

```python
class Approver(ABC):
    """抽象审批人：持有下一环的引用，处理不了就传递下去"""

    def handle(self, request: PurchaseRequest) -> str:
        if request.amount <= self.limit:
            return self._approve(request)
        if self._next is not None:
            return self._next.handle(request)
        return f"申请被拒绝：金额 {request.amount} 元超出所有审批人的权限上限"
```

`main()` 用 `manager.set_next(director).set_next(ceo)` 组装出"经理 → 总监 → CEO"的链，
调用方永远只把申请交给链的第一环 `manager`。

## 文件说明

| 文件 | 说明 |
|------|------|
| `main.py` | `PurchaseRequest`、`Approver` 抽象处理者、`Manager`/`Director`/`CEO` 具体处理者、`main()` 演示 |

## 编译与运行

```bash
python main.py
```

## 要点

1. **请求者与处理者解耦** —— `main()` 只认识链的第一环 `manager`，完全不知道审批最终落在哪一级。
2. **链可以动态调整** —— 插入新的审批层级（如"副总裁"）只需修改 `set_next` 的连接顺序，不改动 `Approver` 内部逻辑。
3. **允许无人处理** —— 链的末端 `CEO.set_next` 未设置，`_next is None` 时给出明确的拒绝信息，而不是静默失败。
4. `set_next()` 返回参数本身（而非 `self`），使得 `a.set_next(b).set_next(c)` 能够连续拼接成 `a -> b -> c`，是本例的一个小技巧。

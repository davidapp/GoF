# Flyweight 享元模式（JavaScript）

## 意图
运用共享技术有效地支持大量细粒度对象的复用。把对象状态拆分为“内在状态”（可在多个对象
间共享、与上下文无关）和“外在状态”（因上下文而异、不可共享），只为内在状态创建共享对
象，从而大幅减少对象数量、节省内存。

## 适用场景
- 系统中存在大量对象，导致很大的存储开销。
- 对象的大部分状态都可以外部化（提取为外在状态）。
- 剥离外在状态后，可以用相对较少的共享对象代替大量对象。
- 应用不依赖对象标识（即不关心两个"看起来一样"的对象是否是同一个引用）。

## 实现方式
`TreeType` 是享元对象，只保存内在状态（名称/颜色/纹理），`draw(x, y)` 方法接收外在状态
（坐标）作为参数。`TreeTypeFactory` 用 `Map` 缓存已创建的 `TreeType`，相同参数只创建一份。
`Tree` 只保存外在状态（坐标），通过引用共享的 `TreeType` 获得内在状态：

```js
class TreeTypeFactory {
  static #cache = new Map();
  static getTreeType(name, color, texture) {
    const key = `${name}_${color}_${texture}`;
    if (!TreeTypeFactory.#cache.has(key)) {
      TreeTypeFactory.#cache.set(key, new TreeType(name, color, texture));
    }
    return TreeTypeFactory.#cache.get(key);
  }
}

class Tree {
  constructor(x, y, treeType) { this.x = x; this.y = y; this.type = treeType; } // 引用共享对象
}
```

## 要点
1. 6 棵树只对应 2 个 `TreeType` 共享对象，树越多、类型越少，节省的内存越可观（真实场景
   可能是十万棵树共享几十种树种）。
2. 关键设计动作是"状态拆分"：把不随对象个体变化的数据（名称/颜色/纹理）识别为内在状态并
   共享，把随对象个体变化的数据（坐标）作为外在状态由调用方持有并传入。
3. 享元对象一旦创建应视为不可变（immutable），否则共享会导致意外的相互影响；本例
   `TreeType` 没有提供任何修改自身字段的方法。
4. 享元模式通常与工厂模式配合（本例的 `TreeTypeFactory`），由工厂负责判断是否已存在可复
   用的实例，调用方无需关心缓存细节。

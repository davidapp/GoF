# Facade 外观模式（JavaScript）

## 意图
为子系统中的一组接口提供一个统一的高层接口，使子系统更容易使用。客户端只需与外观对象打
交道，无需了解各子系统之间复杂的调用顺序和协作细节。

## 适用场景
- 要为一个复杂子系统提供一个简单入口。
- 客户端与多个子系统之间存在很多依赖关系，希望对子系统解耦、减少客户端需要了解的对象数。
- 需要构建多层系统结构，用外观作为每层的入口点，简化层间依赖。

## 实现方式
`Projector`、`Amplifier`、`Lights`、`StreamingPlayer` 是各自独立的子系统类，都有自己的接口
和调用顺序要求。`HomeTheaterFacade` 组合这些子系统，对外只暴露 `watchMovie()` /
`endMovie()` 两个高层方法，内部按正确顺序调用各子系统：

```js
class HomeTheaterFacade {
  watchMovie(movie) {
    this.#lights.dim(20);
    this.#projector.on();
    this.#projector.setInput('HDMI-流媒体播放器');
    this.#amplifier.on();
    this.#amplifier.setVolume(65);
    this.#player.on();
    this.#player.play(movie);
  }
}
```

## 文件说明
| 文件 | 说明 |
|------|------|
| `main.mjs` | 外观模式完整示例：投影仪/功放/灯光/播放器四个子系统，以及协调它们的 `HomeTheaterFacade` |

## 编译与运行
```bash
node main.mjs
```

## 要点
1. 外观模式不封闭子系统的直接访问——需要精细控制的高级用户仍可以绕过 `HomeTheaterFacade`
   直接操作 `Projector` 等子系统类，外观只是提供了一条“更简单的路”。
2. 外观对象承担的是“协调顺序”的职责：先调暗灯光、再开投影仪、切换输入源、开功放调音
   量、最后开播放器——这个顺序被封装在外观内部，客户端不需要知道。
3. 与中介者模式的区别：外观是单向的（客户端 -> 外观 -> 子系统），子系统之间通常不感知外
   观也不互相通信；中介者是多向的，各同事对象通过中介者互相通信。
4. 新增一个子系统（如自动窗帘）只需修改 `HomeTheaterFacade` 内部，不影响客户端调用方式。

# Chain of Responsibility 责任链模式（Java）

## 意图

使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系。
将这些对象连成一条链，并沿着这条链传递请求，直到有一个对象处理它为止。

## 适用场景

- 有多个对象可以处理同一个请求，具体由哪个对象处理在运行时才能确定（如按金额分级审批）
- 想在不明确指定接收者的情况下，向多个对象中的一个提交请求
- 处理者集合及其顺序需要动态指定，而不是硬编码在客户端

## 实现方式

`Approver` 持有 `next` 引用，`approve()` 中先判断自己权限是否足够，
不够则转交给 `next`；`setNext()` 返回参数本身，方便链式拼接：

```java
public abstract class Approver {
    protected Approver next;

    public void approve(PurchaseRequest request) {
        if (request.amount() <= getApprovalLimit()) {
            // 自己处理
        } else if (next != null) {
            next.approve(request);   // 转交下一位
        } else {
            // 链已到头，仍无法处理
        }
    }
}
```

```java
manager.setNext(director).setNext(ceo);   // 组装责任链：经理 -> 总监 -> CEO
manager.approve(request);                 // 请求总是从链的第一个节点开始
```

## 文件说明

| 文件 | 说明 |
|------|------|
| `PurchaseRequest.java` | 请求：采购申请（record） |
| `Approver.java` | 抽象处理者，实现转发逻辑 |
| `Manager.java` / `Director.java` / `CEO.java` | 具体处理者，各自设定审批额度 |
| `Main.java` | 程序入口，组装责任链并提交不同金额的申请 |

## 编译与运行

```bash
cd java/chain-of-responsibility
javac *.java
java Main
```

## 要点

1. **发送者与接收者解耦** —— 客户端只需要拿到链的第一个节点 `manager`，
   不需要知道最终由谁处理请求。
2. **链的组装与业务逻辑分离** —— `setNext()` 负责组装顺序，`approve()` 负责业务判断，
   调整审批顺序（如插入一个副总裁）只需要改 `Main` 中的组装代码。
3. **不保证一定被处理** —— 如果链上没有任何节点能处理（本例中金额超出 CEO 权限），
   请求会被拒绝，责任链模式本身不保证请求一定被处理。

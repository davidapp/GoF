# Template Method 模板方法模式（C++）

## 意图

在一个方法中定义一个算法的骨架，将某些步骤延迟到子类中实现。模板方法使得子类可以在不改变算法结构的前提下，重新定义算法的某些特定步骤。

## 适用场景

- 多个类的算法流程相同或相似，只有个别步骤不同（冲泡茶与冲泡咖啡的流程几乎一致）
- 想通过集中管理公共逻辑来避免代码重复，同时允许子类定制个别步骤
- 需要控制子类的扩展点（子类只能扩展指定的步骤，不能修改算法整体结构）

## 实现方式

`Beverage::prepare()` 是模板方法，规定了固定的四个步骤顺序；`boil_water()`/`pour_in_cup()` 是所有饮料共用的步骤；`brew()`/`add_condiments()` 是抽象步骤，交给 `Tea`/`Coffee` 实现；`wants_condiments()` 是钩子函数，`BlackCoffee` 借此跳过“加调料”这一步：

```cpp
void Beverage::prepare() const {
    boil_water();
    brew();              // 子类实现：泡茶 or 冲咖啡
    pour_in_cup();
    if (wants_condiments()) {   // 钩子：子类可选择性跳过
        add_condiments();
    }
}
```

## 文件说明

| 文件 | 说明 |
|------|------|
| `beverage.h` | 抽象类 `Beverage`（模板方法+钩子）、`Tea`、`Coffee`、`BlackCoffee` 的声明 |
| `beverage.cpp` | 模板方法与各具体步骤的实现 |
| `main.cpp` | 依次冲泡茶、咖啡、黑咖啡，对比固定步骤与差异步骤 |
| `Makefile` | 编译与运行 |

## 编译与运行

```bash
make        # 编译
make run    # 编译并运行
make clean  # 清理
```

## 要点

1. **好莱坞法则** — “不要调用我们，我们会调用你”：基类 `prepare()` 调用子类实现的步骤，而非子类主动调用基类
2. **模板方法通常不应是 virtual** — `prepare()` 定义的是稳定的流程，不希望子类覆盖整体顺序（本例未加 `virtual`）
3. **钩子函数提供有限的定制点** — `wants_condiments()` 让子类可以“跳过”某一步，但不能打乱步骤顺序
4. **复用 + 扩展并存** — 公共步骤只写一次（`boil_water`/`pour_in_cup`），差异步骤由子类各自实现，`BlackCoffee` 还能复用 `Coffee` 的 `brew()`
